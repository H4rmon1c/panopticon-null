## What the repository can show

The atlas has a neutral, searchable Colorado geography index with 4,111 entries: one state, 64 counties, 273 incorporated cities and towns, 178 unified school districts, and 3,595 **provisional** Colorado DOLA district entries. The exact Census and DOLA source bytes are archived outside the public site, with SHA-256 digests and an offline builder. A geography entry means only that the area can be selected; it does **not** assert a surveillance purchase, deployment, or a completed investigation. The Census names and boundaries are as of January 1, 2025. DOLA describes its district layer as preliminary. See [the roster method](../web/panopticon-terminal/geography/README.md).

The [offline municipal directory lead inventory](colorado-municipal-directory.md) now maps 269 Colorado Municipal League listings to the Census roster, with 241 website links. These links help locate document portals for small towns; none is a reviewed collector source or a case. The separate worklist stage still records 4,099 geography entries as `not_started`.

The evidence registry currently binds 49 preserved source files to their official HTTPS URLs and SHA-256 digests. The public website reads only local static files. Browser visits do not query Legistar, Census, or DOLA. The municipal records below use archived Legistar JSON for exact actions and roll calls, and archived official HTML/PDF/DOCX documents for context. An API-backed roll call remains a source dependency at acquisition time; 39 fixed direct-document archive endpoints now support private capture of official HTML, PDF, and JSON without a browser-side API.

## What remains for a credible all-Colorado launch

1. **Investigation coverage:** Thousands of roster entries have no researched decision in this repository. A blank area must continue to say “Records not indexed,” never “no surveillance.” Add state agencies, tribal governments, public authorities, universities, and other bodies through sourced registries; verify district identity before attaching a case.
2. **Document-first discovery:** An opt-in discovery schedule is configured for official HTML meeting calendars in seven jurisdictions and can write private, digest-bound meeting/document link candidates after source review. The production default instead rechecks 12 exact URLs for existing cases. Five exact official event API feeds are configured as separately reviewed fallbacks when their matching HTML calendars fail; the collector reports the failed calendar even after fallback succeeds. Fourteen calendar host/path policies, once reviewed, allow bounded same-host meeting or agenda/minutes PDF capture. Douglas County and Littleton are calendar sources, not investigated cases. [Silver Plume](silver-plume-discovery.md), [Moffat and Simla](moffat-simla-discovery.md), [Del Norte](del-norte-discovery.md), and [Saguache](saguache-discovery.md) have separate, unscheduled small-town HTML/PDF index profiles. The document-index adapter now accepts a configured exact official page and separately reviewed same-host PDF prefix. A durable private [candidate queue](document-first-discovery.md), [source-checked proposal builder](private-case-proposals.md), and verified proposal-to-release bridge exist, but the queue activation matrix is empty and no newly discovered proposal has passed release. Add historical calendar paging, reviewed source profiles for the remaining jurisdictions, pre-index artifact backfill, and more source-specific claim verifiers. Use official API JSON where it supplies an exact vote or another necessary public fact absent from a document; keep the public site independent of live APIs.
3. **Provenance and corrections:** The five-case release requires raw bytes and independent private HTTPS fetch receipts for every published source. Each fact has an exact locator; incomplete or mismatched roll calls, failed motions mislabeled as approvals, changed source bytes, and mismatched jurisdiction IDs block release. A tested withdrawal flow removes rejected cases and keeps a noindex notice at the old share URL. A durable person record still needs official role and term evidence plus identity disambiguation across decisions; names and vote IDs alone are insufficient to join officeholders over time. Source a portrait for each named official where the public body publishes one; retain an explicit gap when it does not.
4. **Publication scale:** A versioned static alerts/news API and coverage report are generated from every release. The exporter combines released manifests and freshly verified proposal inputs into a static snapshot with a distinct social page per decision. As coverage grows, split the dataset into bounded jurisdiction shards or add a read-only self-hosted API. Keep synthetic data and private collector state out of the release.
5. **Operations:** The owner purchased a Namecheap Magnetar VPS; its IP is pending. Finish provisioning, configure `panopticon.fail` to point to it, finish source-level policy reviews, run the collector under systemd, monitor stale sources and failed jobs, and test backup/restore and Caddy TLS on the actual server. No server configuration or DNS cutover has been performed.

The current roster is a discovery scaffold, not a claim of complete legal-government coverage or complete surveillance-contract coverage. The launch count should report **published evidence-backed decisions and reviewed source reach** separately from geography entries.
