# Colorado coverage inventory — 2026-11-10

The [Colorado coverage contract](colorado-completeness-contract.md) sets the target for every public body regardless of population, named-vote and portrait provenance, API fallback, and explicit missing-record states.

## What the repository can show

The atlas has a neutral, searchable Colorado geography index with 4,111 entries: one state, 64 counties, 273 incorporated cities and towns, 178 unified school districts, and 3,595 **provisional** Colorado DOLA district entries. The exact Census and DOLA source bytes are archived outside the public site, with SHA-256 digests and an offline builder. A geography entry means only that the area can be selected; it does **not** assert a surveillance purchase, deployment, or a completed investigation. The Census names and boundaries are as of January 1, 2025. DOLA describes its district layer as preliminary. See [the roster method](../web/panopticon-terminal/geography/README.md).

The evidence registry currently binds 49 preserved source files to their official HTTPS URLs and SHA-256 digests. The public website reads only local static files. Browser visits do not query Legistar, Census, or DOLA. The municipal records below use archived Legistar JSON for exact actions and roll calls, and archived official HTML/PDF/DOCX documents for context. An API-backed roll call remains a source dependency at acquisition time; 39 fixed direct-document archive endpoints now support private capture of official HTML, PDF, and JSON without a browser-side API.

## What remains for a credible all-Colorado launch

1. **Investigation coverage:** Thousands of roster entries have no researched decision in this repository. A blank area must continue to say “Records not indexed,” never “no surveillance.” Add state agencies, tribal governments, public authorities, universities, and other bodies through sourced registries; verify district identity before attaching a case.
2. **Document-first discovery:** The default schedule is configured for official HTML meeting calendars in seven jurisdictions and writes private, digest-bound meeting/document link candidates after source review. Five exact official event API feeds are configured as separately reviewed fallbacks when their matching HTML calendars fail; the collector reports the failed calendar even after fallback succeeds. Fourteen calendar host/path policies, once reviewed, allow bounded same-host meeting or agenda/minutes PDF capture. Douglas County and Littleton are calendar sources, not investigated cases. [Silver Plume](silver-plume-discovery.md), [Moffat, and Simla](moffat-simla-discovery.md) have separate, unscheduled small-town HTML/PDF index profiles. A durable private [candidate queue](document-first-discovery.md) and [source-checked proposal builder](private-case-proposals.md) now exist, but the queue activation matrix is empty and proposals do not publish. Add historical calendar paging, reviewed source profiles for the remaining jurisdictions, pre-index artifact backfill, and a verified proposal-to-release adapter. Use official API JSON where it supplies an exact vote or another necessary public fact absent from a document; keep the public site independent of live APIs.
3. **Provenance and corrections:** Capture raw bytes and independent private HTTPS fetch receipts for every published source. Bind each fact to an exact locator; reject incomplete or mismatched roll calls, failed motions mislabeled as approvals, changed source bytes, and mismatched jurisdiction IDs. Add an operator correction and withdrawal flow before continuous auto publication. A durable person record also needs official role and term evidence plus identity disambiguation across decisions; names and vote IDs alone are insufficient to join officeholders over time. Source a portrait for each named official where the public body publishes one; retain an explicit gap when it does not.
4. **Publication scale:** The exporter can combine the eight version 2 manifests and the original Colorado Springs case into one preview snapshot, and generate a distinct social page per released decision. As coverage grows, split the dataset into bounded jurisdiction shards or add a read-only self-hosted API. Keep synthetic data and private collector state out of the release.
5. **Operations:** Provision the chosen Namecheap VPS, configure `panopticon.fail` to point to it, finish source-level policy reviews, run the collector under systemd, monitor stale sources and failed jobs, and test backup/restore and Caddy TLS on the actual server. No VPS or DNS cutover has been performed.

The current roster is a discovery scaffold, not a claim of complete legal-government coverage or complete surveillance-contract coverage. The launch count should report **published evidence-backed decisions and reviewed source reach** separately from geography entries.
