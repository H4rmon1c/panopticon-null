# Official portraits beside recorded votes

The decision page joins a portrait to a `RECORDED_VOTER` entity by its exact entity ID and name. For version 2 records it also checks the Colorado geography ID, Legistar client, and official `VotePersonId` from the vote record, preventing reuse on a different voter entity. Commerce City profile pages do not themselves print the Legistar person ID. Six profile names match the vote names exactly; three use the separate [first-party identity bridge](portrait-identity-bridges.md). Ambiguous names remain unbound. Portraits never establish a vote, contract, office term, or what the person looked like on the vote date.

The first version 2 portrait set covers all nine people named in Commerce City's direct roll calls for Ordinances 2755 and 2756. Those decisions remain preview-only. Each [registry entry](../web/panopticon-terminal/portraits/portraits.js) identifies the official city profile, the image URL shown on that page, the untransformed PNG path on the same city host, the exact preserved HTML and PNG SHA-256 digests, and the retrieval date (2026-11-10). The raw profile pages are in [`fixtures/atlas/portrait-sources`](../fixtures/atlas/portrait-sources); the original 720×720 PNG bytes are in [`web/panopticon-terminal/portraits`](../web/panopticon-terminal/portraits). `scripts/validate.mjs` checks the page's heading, main image locator, local file type and digest, and the voter identity binding before publication.

The vote card uses the preserved local image as a cropped thumbnail and offers **Open preserved image** for the complete local file, plus a link to the official source page. It makes no browser request to the municipal image host. The profile pages do not date the photos, so each new entry records `portrait_date: not_established`. The source PNG is the full file served at the page's image path; there is no claim that it is a photographer's original or depicts the official at the decision date.

Three Commerce City portraits needed an extra [first-party identity bridge](portrait-identity-bridges.md). The city's **Steve Douglas** and **José Guardiola** profile names differ from the vote API names; preserved official Person records tie the vote IDs and names to matching city email addresses on the profiles. Rocky Teter's Person record and profile heading match, while the city image alt text misspells the surname. The email addresses are used only for verification and do not appear on vote cards. A missing portrait shows initials and **Official portrait: not yet verified**. Colorado Springs portraits retain their earlier image registry and are still byte-checked; their older profiles do not yet have the same preserved-page proof.

The seven Castle Rock direct voters also have [town portrait provenance](castle-rock-portraits.md). The town's profile pages were observed through browser DOM extracts because direct HTML requests returned 403; the image files and Legistar Person responses were preserved as raw bytes. The DOM extracts are weaker acquisition evidence than an HTTP response capture and are labeled as such. Their case is still preview-only.

For another jurisdiction, preserve the official role/profile page and exact image response, pin both digests, record an exact page locator, and add a registry entry only after the page binds the image to the same named voter. If the vote is recorded only for a consent motion, show the names under that motion as context and leave item-specific votes not established. Source-level acquisition review and a case release remain separate gates; there is no per-record human approval requirement. The publication step filters portrait assets and the browser registry to voters in the released snapshot, so preview-only portraits do not leak into the public site.
