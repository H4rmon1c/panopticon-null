# Colorado production security review — November 10, 2026

This was a defensive source review and local adversarial regression pass over the Rust collector, document sandbox, release checks, browser, and new static API/operations package. No VPS address or SSH access was available. No external system was attacked. This is evidence of specific controls tested, not a claim that the service is immune to a well-resourced attacker or a substitute for an independent penetration test.

## Findings repaired

| Finding | Impact and preconditions | Repair and regression |
| --- | --- | --- |
| Whole host `/etc` was mounted read-only in the PDF sandbox | High confidentiality impact if an extractor is compromised: read-only access still exposes any configuration or credentials readable by the service account. The old broad `/nix` mount also exposed package-manager state. | Mount only font configuration and the linker cache under a private, read-only `/etc`; expose `/nix/store` instead of `/nix`. Real sandbox tests prove host `/etc/passwd`, `/etc/panopticon`, and `/nix/var` are absent, host files remain inaccessible, and writes fail. |
| Error sanitization repeatedly counted the accumulated string | Medium/high availability impact from a failed extractor producing a large error stream: quadratic CPU work occurred in the host process after the extractor's resource limits ended. Its character count also failed to enforce a UTF-8 byte limit. | Linear byte accounting, zero-byte handling, multibyte and invalid UTF-8 cases, and large-input regression. |
| Extractor output was parsed more deeply than necessary on the host | Medium availability risk after hostile or compromised extractor output: OCR images were fully decoded merely to read dimensions, and XML/TSV was read before an explicit host-parser byte bound. | Read image dimensions without decoding pixels, reject dimensions beyond the 4000-pixel renderer limit, and cap XML/TSV reads at 20 MiB before parsing. Tests use a sparse oversized text file and an image beyond the dimension limit. The sandbox's private `/tmp` now has a size cap as well. |
| IPv6 documentation prefix missing from public-address classification | Low policy-boundary defect: `3fff::/20` could be classified as a public connection target despite its reserved documentation purpose. Exploitation would also need a route and reviewed host resolving there. | Reject the full prefix, including its final address, while keeping a real public IPv6 control accepted. [IANA's IPv6 special-purpose registry](https://www.iana.org/assignments/iana-ipv6-special-registry) identifies this block as non-global documentation space. |
| Direct vote rows could disagree with their cited vote value in browser validation | Medium integrity risk from a malformed static export or tooling change: a row with an existing evidence ID could display the opposite vote while passing the JavaScript validator. Rust source verification remains the authoritative raw-evidence check. | Require the direct vote's scalar value or legacy combined name/value claim and locator to agree. Regression mutates Colorado Springs and Commerce City votes and substitutes unrelated evidence. This does not cryptographically authenticate a server compromised enough to rewrite all data and validators. |
| A long-open page retained its first snapshot indefinitely | Low freshness/correction risk: a withdrawal could remain displayed until a manual reload. | Public atlas and decision pages check for a validated content change every 60 seconds while visible and when becoming visible, then reload the whole version. Concurrent checks share a request; network timeout is 15 seconds; invalid preview data never replaces the current version. Mere export-clock changes do not cause reloads. |
| Root installer could follow a service-planted directory symlink on a later run | High privilege impact after service-account compromise followed by an administrator rerunning installation: `install -d -o panopticon` could change ownership and permissions on the symlink target. A temporary-directory reproduction confirmed this behavior. | Directory installation now walks components using directory file descriptors and `O_NOFOLLOW`, then changes only the opened inode. The regression preserves a planted target's permissions. The installer also checks the release executable's root ownership and write permissions. |
| Shell lock creation could truncate a planted symlink target | Medium integrity impact from poisoned private lock paths: opening a lock with shell `>` could truncate a service-writable public artifact before validation. | A shared helper opens nontruncating, no-follow regular files, verifies inode identity, and carries checked lock descriptors across execution. The regression proves target content and permissions are unchanged. |
| Backup omitted durable document-discovery artifacts | Medium recovery impact: restoring SQLite, raw evidence and canonical records alone lost filesystem candidate manifests and archive receipts needed by the document queue. | Backups now include optional `discovery-candidates`, `discovery-archives`, and configured private proposal inputs, alongside a coherent SQLite backup and published release/API history. Actual off-server restore remains a deployment gate. |

## Verified existing controls

- HTTP uses HTTPS on port 443, rejects credentials and unreviewed hosts/paths, rejects mixed public/private DNS answers, binds the real transport to the validated addresses, disables proxies and automatic redirects, caps each read, and preserves completed failure receipts. Conditional `304` reuse requires an existing exact raw-byte baseline and does not create invented evidence.
- Archive capture checks exact source configuration and unexpired source review. Source provenance and preserved bytes are rechecked for public release. A changed required digest, absent vote proof, failed motion mislabeled as approval, or consent-block vote presented as an item vote prevents release.
- The PDF subprocess has isolated network and PID namespaces, a cleared environment, bounded address space, CPU, file size and wall time, read-only staged originals, private capture files, and no unsandboxed production fallback. Staged inputs and host-read output reject symlink paths.
- The browser renders record strings through escaping or text nodes; the existing hostile-metadata test and source/privacy validator pass. The API generator selects fields from the public snapshot, validates canonical URLs, bounds inputs/output, escapes JSON markup characters, preserves stable change IDs, and requires an explicit withdrawal when an active record disappears.
- The Castle Rock revision was independently checked against both exact preserved SHA-256 values. Only two ASP.NET hidden values and eleven resource-cache timestamps differ. The volatile HTML is historical context; no released factual locator depends on it. The revised case still passes the raw-source release path.

## Remaining production conditions and limits

1. Run the real PDF integration test **as the service user under the deployed systemd restrictions**. A workstation pass does not establish Ubuntu/AppArmor policy, rootless namespaces, Caddy TLS, firewall rules, DNS, filesystem ownership, or actual timer behavior on the new VPS.
2. Apply a disk quota or separate bounded filesystem for extraction/collector temporary data, and alert on disk/inode usage. Per-file size limits, process limits and timeouts do not impose an aggregate quota on all files a compromised native extractor might create in its writable host directory. Keep credentials out of all mounted runtime/package directories.
3. Keep the repository and executables administrator-owned; the collector must not be able to replace its own code, service units or Caddy configuration. Separate site-readable releases from private databases, raw evidence and backup credentials. The operating-system/kernel and provider control plane remain trust boundaries.
4. Test encrypted off-server restore, withdrawal/rollback, source-review expiry and stale/failed health states on the real server. Set a tested retention policy and use append-only backup access or provider-enforced retention where available so stolen VPS credentials cannot delete every recovery point. Monitor the health endpoint from another system; a process on a powered-off or disconnected VPS cannot notify the operator itself. A publication timestamp alone does not prove a fresh source fetch.
5. Source access reviews expire, and new document portals still need reviewed configuration and claim verifiers. Preserve a visible degraded/unknown coverage state rather than treating a silent collector or an empty area as a negative surveillance finding. No code should automatically extend a review or manufacture a missing public fact.
6. Static serving reduces exposed application code but does not prevent volumetric denial of service, an upstream source becoming dishonest, stolen administrator credentials, supply-chain compromise, or an undiscovered sandbox/kernel exploit. Use provider DDoS protection, supported OS updates, restricted SSH access, monitored backups and independent review as part of operation. The future posting bot should have its own narrow credentials and consume only healthy, validated API revisions; posting remains unconfigured.
